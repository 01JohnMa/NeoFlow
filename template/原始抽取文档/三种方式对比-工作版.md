# 原始抽取文档三种策略对比（固定空 JSON 模板）

## 模板边界

- 抽取提示词直接使用：`template/OCR训练-基本信息-药物注册类/1-空JSON-药物注册类.json`。
- 该模板固定包含 **40 个字段**。
- 输出契约按该模板：顶层 `scene/trialType/registrationType`，`fields[]` 保留原声明并新增 `value/confidence/source`。
- 三种策略使用同一空 JSON、同一批文档和同一模型配置；评分时仅将 `fields[].value` 摊平比较。
- 旧报告使用派生 JSON Schema，不能作为本轮结果；本文件已覆盖为固定模板结果。
- gold 是 `source-reviewed-draft/*.json` 的工作版；每份文档只统计原文有证据的字段：BMS 22 个、CTP 24 个、FOT12 23 个、西达本胺 22 个，合计 91 个“文档-字段”评分项。91 不是模板字段数量。长列表、同义词、单位和中英文等价仍需业务语义复核。

## 结果解释

- `full_document` 仍是整体最快；在固定模板下质量最高或并列最高。
- `source_page_routed` 把 Parse 页数从 280 降到 109，但平均耗时反而升到 74.27 秒，主要成本来自页索引、Embedding 和候选页解析；质量只在 CTP 上超过全文，BMS 和西达本胺明显下降。
- `agentic_source_page_routed` 只再减少 22 页，却达到 102.10 秒/文档；Agent 循环没有带来稳定质量收益。
- CTP/FOT12 的 routed 差异主要是长入排标准、终点和产品表格被截断；BMS 受扫描 OCR/图片向量影响；西达本胺还存在开放期 20 例与双盲期 328 例的分期语义问题。
- 分数是保守 exact 字段匹配下限。例如 `240例` 与 `240名受试者` 应做业务等价归一，不能直接按字符串差异判错。

## 当前结论

本轮固定空 JSON 后，仍不能把 `source_page_routed` 或 `agentic_source_page_routed` 设为默认。`full_document` 保持基线；source-first 继续作为可选实验，后续应先补章节锚点、表格整页、列表完整性校验和业务语义评分，再做 A/B。
