# 真实案例 4 说明：苹果酸阿莫曲坦片（CTS1248）

本案例与《2-示例-填好的JSON.json》配对使用：示例 2 是手工构造的教学样例，本案例以**真实临床试验方案**（《样例PDF-苹果酸阿莫曲坦片临床试验方案-CTS1248.pdf》，42 页）为依据，按《1-空JSON-药物注册类.json》的字段契约整理，可对照 PDF 逐字段核查。2026-09-25 直接读取原始 PDF 并渲染关键页复核，没有调用 NeoFlow 抽取服务生成标准答案。

下文的“物理页”从 PDF 封面第 1 页开始计数；封面无文内页号，此后的文内页号比物理页小 1。各字段 `source` 已同时注明两种页码。

## 这份案例额外演示的规则点

| 规则点 | 本案例表现 |
| --- | --- |
| 宁缺勿错：未找到直接依据的字段不输出 | 原文未找到**本试验分期**的直接声明，不能将“注册临床研究”或诊断标准 ICHD-Ⅲ 推导为 III 期；§3.2 的“筛选期、双盲治疗期”是研究流程阶段，也不是 I/II/III/IV/BE 分期。因此 `trial_phase` 整个字段不输出；同理缺省的还有 `project_short_name`、`registration_no`、`registration_date`、`human_resource_review`、`insurance_flag`、`project_owner_email`、`drug_en_name`（物理第36页参考文献中的 AXERT®/Almotriptan malate 指原研说明书，不是本研究产品英文名称声明）、`drug_registration_class`（原文未声明注册分类，不据药名、药理或批件号推断）、`combination_products`（应急用药芬必得不作为预定联合产品）、`nmpa_acceptance_no`、`nmpa_date`（方案引用了批件号，但未附含受理号和批件日期的批件原件），共 12 个字段缺省 |

| 归纳有据才输出（`project_scope` vs `drug_registration_class`） | `project_scope`：§22.2 列出 8 个研究中心且全为国内医院，可归纳为「国内多中心」→ **输出**；`drug_registration_class`：原文无注册分类字样（§1.3 仅述其为 5-HT1B/1D 受体激动剂），即使批件号编码可推断也 **不输出** |

| number 与样本量口径 | 「计划纳入 240 例受试者（试验组和对照组各 120 例）」→ `planned_subject_count` = `240`、`sample_size` = `240例`。按用户已确认口径，后者只保留总数和单位；§5的初步计算“50对”不是最终计划入组数 |

## 统计

- 空 JSON 模板 40 个字段，本案例实际输出 **28 个完整字段对象**、缺省 12 个（见上表）；其中两个日期值包含上述月粒度归一约定。
- 旧文件实际有30个对象：28个带值字段，外加没有 value/confidence/source 的 NMPA受理号、NMPA日期两个占位对象。本次删除了这两个占位对象，令结构与“无依据则整个字段省略”一致。
- 教学样例不是本案例事实或字段数量的依据，不再沿用“37/38”的过时统计。
