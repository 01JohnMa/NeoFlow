# 真实案例 4 说明：苹果酸阿莫曲坦片（CTS1248）

本案例与《2-示例-填好的JSON.json》配对使用：示例 2 是手工构造的教学样例，本案例是**真实临床试验方案**（《样例PDF-苹果酸阿莫曲坦片临床试验方案-CTS1248.pdf》，42 页）按同一提示词提取的结果，可对照 PDF 逐字段核查。

## 这份案例额外演示的规则点

| 规则点 | 本案例表现 |
| --- | --- |
| 宁缺勿错：全文找不到依据就不输出 | 方案通篇**未标注试验分期**（原研已上市品种的注册验证性研究，无 I/II/III/IV 期或 BE 字样），`trial_phase` 整个字段不输出；同理缺省的还有 `project_short_name`、`registration_no`、`registration_date`、`human_resource_review`、`insurance_flag`、`project_owner_email`、`drug_en_name`（参考文献里的 AXERT® 是原研制剂名，不是本研究产品的英文名）、`drug_registration_class`（原文仅述其为 5-HT1B/1D 受体激动剂，无「化学药」等注册分类字样，不据批件号编码推断）、`combination_products`（单药研究，应急用药芬必得≠联合产品），共 10 个字段缺省 |
| enum 必须归一到选项原文 | 「随机、双盲、安慰剂平行对照」→ 盲法只取「双盲」；「注册临床研究」→「注册类」；「多中心临床研究」→ 是否多中心=「是」 |
| 归纳有据才输出（`project_scope` vs `drug_registration_class`） | `project_scope`：§22.2 列出 8 个研究中心且全为国内医院，可归纳为「国内多中心」→ **输出**；`drug_registration_class`：原文无注册分类字样（§1.3 仅述其为 5-HT1B/1D 受体激动剂），即使批件号编码可推断也 **不输出** |
| 日期月粒度 → 低置信归一 | 方案只给「2014.11-2015.4」，归一为 `2014-11-01` / `2015-04-30`，confidence 降到 0.66~0.68，source 里注明归一方式 |
| 有据即填（与示例 2 的 control_products 缺省对照） | 本方案 §6.1 明确「选用安慰剂作为本试验的对照产品」，`control_products` 输出该行 |
| **product[] 行内宁缺勿错** | 对照产品=安慰剂只填有依据的子字段：`name`（§6.1）、`specification_model`「0mg/片」与 `dosage_form`「片剂」（§6.2 对照药栏）；`name_en` 与 `drug_registration_class` PDF 无依据（安慰剂非注册药品）→ **子字段直接省略，不造空串**；confidence/source 仍在字段级 |
| number 纯数字 | 「计划纳入 240 例受试者（试验组和对照组各 120 例）」→ `planned_subject_count` = `240`，单位与分组说明留在 `sample_size`（string）里 |
| 同一人多来源交叉印证 | `project_owner` 于生元来自封面「临床试验负责人」，其手机号来自 §22.3 联系方式表（01 中心），置信度中等（0.75） |

## 统计

- 空 JSON 模板 38 个字段，本案例输出 **28 个**、缺省 10 个（见上表）。
- 与示例 2（37/38，仅 control_products 缺省）对照即可向 OCR 同学说明：**缺省数量随资料而变，标准只有一个——PDF 里有依据才输出。**
